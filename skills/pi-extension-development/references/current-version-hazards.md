# Version and Distribution Hazards

## Evidence and support policy

The supported baseline is **official Pi 1.0.0**, source [`a13d35a742c6ef8462812a28fbe1d8c8b7431c32`](https://github.com/earendil-works/pi/tree/a13d35a742c6ef8462812a28fbe1d8c8b7431c32), checked 2026-10-01 against the published public SDK `dist/index.js`, bundled CLI `dist/bundle/cli.js`, declarations and source. The eight Pi packages (coding-agent, agent-core, ai, tui, chord, telemetry, codemode, mcp) are 1.0.0; host TypeBox is **1.3.27** and the qualification Node is **24.21.0**. Companions may be nested under coding-agent's `node_modules`; resolve from the selected SDK, not the consumer root.

The October 1 baseline above and `SKILL.md`'s `last-verified-pi`/`official-source` fields remain historical evidence, not a new qualification claim. The October 9 source audit distinguishes:

The installed fork is no longer the five-feature 1.0 candidate. Its [revision-matched `FORK.md`](https://github.com/fitchmultz/pi/blob/c2031ab702c8815cd738a32664293541ad184ed6/FORK.md) owns the inventory: restart, detached background commands, instruction groups, JSON Read selection, compact activity (`boolean | "hybrid"`), immutable fork updates, Termux handling, complete native working-session state, credential isolation, fallback auth, opt-in performance warnings, temporary passive tracing, and Cloudflare Claude-ID canonicalization, plus retained correctness fixes. Those include native exact-Astra Ultrafast cost estimates gated by terminal tier confirmation; source/offline checks do not establish live billing.

Resolve installed and intended revisions separately, then consult that revision's `FORK.md` and emitted exports. Keep live resources/settings/runtime untouched during isolated qualification; matching version strings do not identify matching artifacts. Historical reports retain the versions and checks they actually exercised.

Canonical context, retain-none compaction, actionable boundaries and replacement callbacks date to **0.87.0**, not 1.0. Native tool composition dates to **0.99.0**. The hard 1.0 removals are experimental agent-core harness exports; fullscreen is now the default. Check every crossed changelog rather than attributing all existing APIs to this release.

## Portable session and lifecycle contracts

- Use `DefaultResourceLoader`, `createAgentSession`, `SessionManager`, `ModelRuntime`/`ModelRegistry`, and `AgentSessionRuntime` for ordinary extensions and hosts. `CreateAgentSessionOptions.tools` is a **name array**; definitions belong in `customTools`. A supplied resource loader must be reloaded by its owner. SDK sessions do not automatically load CLI builtins; add their factories and call `session.bindExtensions()` when needed.
- `SessionManager` owns finalized provider context. SDK owners append/navigate through it then `session.refreshContext()`, or create a session with a populated manager. Assigning `session.agent.state.messages` is not a supported context rewrite. Extensions get a read-only manager: use public message/append APIs or boundary drafts, not private casts.
- `message_end` is dispatched **before** the message is appended. Use its authoritative message value for message-local work; don't assume it is already in `getBranch()`. `turn_end` resolves persisted assistant/tool-result IDs, composes drafts across handlers, then commits **after** handlers finish. Preserve earlier proposals with `{ entries: [...event.entries, draft] }`.
- `custom` drafts persist non-model state; `custom_message` adds model content; `context_edit` changes/omits active-branch content without erasing raw history, usage or UI; `compaction` with `firstKeptEntryId: null` retains none of the preceding conversation while carrying current system/tool state. Do not request unconditional continuation: the preview must contain runnable context or queued input.
- `agent_end` finishes one low-level loop, not retries, compaction recovery or queued continuations. `agent_before_settle` is the final actionable boundary; `agent_settled` is notification-only and defers newly scheduled work until handlers finish. Use `AgentSession.waitForIdle()`/command-context idle, never low-level `session.agent.waitForIdle()`, for final local completion. Extension-owned detached jobs still have their own completion contract. Avoid awaiting a run's idle from a handler that run is waiting for.
- `context` receives conversation without system messages; the host restores prompt/tools. `context_with_system` owns the full output: preserve the leading system declaration at index zero and later tool updates in their positions. No old fork native-head restoration guarantee exists on the 1.0 targets. Request-local transformations do not persist context edits. `before_agent_start.systemPromptOptions` is mutable, `systemPrompt` is readonly; continuations do not rerun that hook and forced prompts can replace system-only decoration.
- After committed `newSession`/`fork`/`switchSession`, old `pi`/`ctx` actions and getters are stale. Capture plain data first and do session-bound follow-up only with `withSession(freshCtx)`. After `await ctx.reload()`, return; reload has no fresh-context callback. Official reload clears factory caches and reinitializes resources. Do not carry old fork restart-only advice into the official-derived target.
- Runtime replacement aborts/settles outgoing work, awaits `session_shutdown`, tears down host UI and disposes before creating the replacement. Factory failure does not restore the disposed old runtime. Rebind subscriptions through `runtime.setRebindSession`; synchronous host UI teardown uses `setBeforeSessionInvalidate`. Direct `session.dispose()` is synchronous invalidation/abort/listener cleanup, not the awaited shutdown lifecycle of `runtime.dispose()`.
- Committed replacement and interactive `/tree` abort/persist active work; programmatic navigation rejects while active. Later unstarted sequential siblings may remain unmatched after abort: wait for final idle if balanced history is required; never fabricate tool results. Preserve legacy saved-session recovery when removing obsolete runtime paths.

`pi-posthorse` is **portable on official 1.0** through public retain-none compaction/boundaries. Do not declare a blanket fork-only exception or require checkpoint APIs for ordinary rollover. Validate prompt/tool retention, queued input, errors, threshold/overflow, resume and legacy journal recovery.

## Tools, concurrency and policy

- Tools run in parallel by default; preflight is ordered, completion events follow finish order and persisted results follow assistant source order. Key state by `toolCallId`. Any `executionMode: "sequential"` sibling serializes the whole batch, not only that resource.
- `withFileMutationQueue(path, fn)` covers the whole same-file read/modify/write window and releases on failure. It is **process-local**, resolves existing realpaths but uses a lexical path for missing files, and is not a multi-file transaction or cross-process lock. Keep batch planning/rollback, symlink safety and external ownership where required.
- `prepareArguments` precedes validation; mutable `tool_call.input` follows it and is not revalidated. Preserve schema/trust invariants yourself. A blocked call's `terminate` suppresses follow-up only when all finalized sibling results terminate. Changing active tools is not a promise of revoking already-preflighted sibling references.
- Tool-context `ctx.executeTool()` uses validation/hooks/permissions, child IDs and `parentToolCallId`. Unknown/blocked/throwing calls resolve `isError: true`, not rejection. Nested-call records are bounded metadata, not durable raw results; usage aggregates onto the parent, so don't count twice. Raw tool execution bypasses this boundary. Late updates after settlement are ignored.
- Native exposure is a policy choice: direct is callable while active; model-only is never nested-callable; codemode/deferred are callable whenever registered even if inactive; hidden is unreachable. `defaultActive: false` is not deferred exposure. Namespace/annotations and `prepareLoadout` do not enforce permissions or instruction-before-effect gates.
- Preserve `isError`, meaningful content and top-level usage. An output schema promises successful `structuredContent`. Content replacement drops old structured content unless supplied consistently; do not leak stale machine-readable secrets after redaction.
- `defaultTools` reload enables newly added defaults without overriding explicit `tools`/`noTools`; do not delete necessary resume restoration without exercising that SDK path. `sendUserMessage` expands commands/skills/templates only with `expandPromptTemplates: true`; context-only `sendMessage({ triggerTurn: false })` is not steering.

## Current fork boundaries

The installed discovery builtin emits `pi:instruction-groups` **synchronously during session_start** with `{ register(group), isManaged() }`. A group is `{ name, description, tools, instructions(ctx) }`; `discover_tools` accepts optional `enable: string[]`. Register synchronously with extension-owned tool names/instructions. Enabling restores only previously selected tools for a subsequent turn: optional/excluded/hidden tools stay restricted, and same-assistant discovery/action calls are blocked even in sequential execution. Read the selected fork's `docs/instruction-groups.md` for readiness, positional declarations and branch/compaction recovery. This replaces old `ToolDefinition.discovery`, `sectionTools`, provider allowlists and settings inventories; do not resurrect them. Preserve complete official prompt-section/tool exposure and existing instruction/approval gates when the collector is absent or unmanaged. Native BM25 `tool_search`, provider-native search and MCP gateways are different mechanisms, not substitutes for group instructions. This source contract is not full qualification of another revision.

Read JSON selection belongs to core `createReadToolDefinition`, so native cwd wrappers inherit it. `compactView` is a global `boolean | "hybrid"` setting, default off; preserve the user's selection and do not invent renderer properties from its name. Restart/background commands are builtin extensions using public lifecycle APIs, not checkpoint APIs. Inspect the selected revision's help/source before relying on their details. `pi update --fork` is runtime delivery, not extension update, and needs explicit cutover authority.

The 1.0 rebuild dropped checkpoint/acquireCheckpoint, metadata/revision cursors, `recordUsage`, `ContextUsage.source`, Bash-cwd/publisher hooks, mutation-key exports, `unregisterCommand`, `persistOnCancel`, active-tool preservePending, extra retry events and extra TUI/RPC APIs. Current native working-session and auth-fallback APIs are separate additions, not restorations of that old stack. Do not keep unsupported branches or no-op shims. Saved data compatibility is a separate requirement: retain old journal readers/recovery when needed.

## Published configuration schemas

The audited **unreleased f1b2e77f** snapshot publishes these files under the coding-agent package root (repository prefix `packages/coding-agent/`):

| Document | Schema path |
| --- | --- |
| Themes | `schemas/theme.schema.json` |
| Keybindings | `schemas/keybindings.schema.json` |
| Models | `schemas/models.schema.json` |
| Settings | `schemas/settings.schema.json` |

Editor URLs use `https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/schemas/<name>.schema.json`; theme metadata must no longer point into `src/modes/interactive/theme/`. Pi does not fetch `$schema` URLs to load configuration. Use the exact host's shipped schema/native loader for acceptance. These schema files, extra-theme-key rejection, canonical key validation and positive model token-count requirements are new in this snapshot, not implied by the shared 1.1.0 version string. The inherited rules below already apply on official 1.0.0 and installed c2031.

- In f1b2e77f, themes additionally reject extra top-level fields and unknown `colors`/`export` keys. Existing theme rules remain: put reusable custom colors in `vars`, use documented export backgrounds, and resolve missing/circular variable references through the native loader. Names cannot contain `/`; `system` is reserved. Optional scrollbar/search/`thinkingMax` tokens retain native fallbacks; do not duplicate a token inventory or add needless colors.
- Key values use the native `KeyId` spelling and case, including `pageUp`/`pageDown`, with lowercase `ctrl`, `shift`, `alt`, `super` modifiers, no duplicates, and valid base keys. Examples: `ctrl+shift+x`, `alt++`; not `Ctrl+X`, `option+x`, or `ctrl+ctrl+x`. Extension-owned action names remain allowed; schema validation is not a global action-name allowlist.
- In f1b2e77f, `models.json` definitions and overrides require supplied `contextWindow` and `maxTokens` to be positive numbers. Zero is not “unlimited”; omit optional values or supply verified positive limits.
- Existing official 1.0.0/c2031 validation already requires positive integer image dimensions/byte/count limits, JPEG quality of 1–100, and positive supplied prompt-cache lifetimes.
- Settings allow extension-owned keys. Do not make Pi's schemas a strict validator for unrelated extension configuration. When adapting a fork settings schema, retain `compactView: boolean | "hybrid"` and existing resource filters.

## SDK, JSON and RPC traps

- Inspect exported interfaces over stale SDK prose: no `continueSession` option; `SettingsManager.create(cwd, agentDir?, options?)` is positional; `SessionManager.list(cwd)` selects a project, `listAll()` all normal projects, and its optional string is a custom session directory. Resources use `sourceInfo`, not obsolete `source`/location fields.
- JSON starts with a `type: "session"` header. Header/entry timestamps are ISO strings, message timestamps milliseconds; compaction uses `firstKeptEntryId`. Wire `message_update` is delta-only, unlike in-process events. Accumulate by content index until authoritative `message_end`; cumulative usage may be zero until completion.
- Parse incremental UTF-8, split only LF, accept trailing CR and flush EOF. Node readline also splits Unicode separators valid inside JSON strings. Do not pass all stdout through as a successful assistant answer; inspect the final assistant's stop reason, process result and cancellation.
- RPC input receipts distinguish **started/queued/handled**. Handled means no new run; queued is not completion. Install listeners before prompt, inspect disposition and clean up listeners on every path. Official `RpcClient.waitForIdle`/`collectEvents` await a **future** settled event; `promptAndWait` installs first but ignores handled disposition and can timeout on a handled command. There is no target-fork `wait_for_idle`, attach_tui or pending extension UI state contract.
- `get_available_thinking_levels` returns `{ data: { levels } }`; the client unwraps it. Re-query after model changes. `get_commands` uses `sourceInfo`. Direct RPC bash honors `user_bash`, emits correlated `bash_execution_update`, and accepts raw `excludeFromContext: true`; the bundled client bash helper doesn't expose that option.
- Native bash injects session/model/reasoning variables unless `exposeSessionEnvironment: false`; user-entered `!`/`!!` do not. Use explicit physical Node and `env -i` with isolated HOME/agentDir for tests, rather than inherited `PI_*` state or mise/asdf shims that fail under a private HOME.

## Models and providers

- Ordinary pi-ai ESM root has types, StringEnum, streams/utilities, `createModels`/`createProvider`, not global `getModel`/`stream` dispatch. Use extension `ctx.modelRegistry` or standalone `ModelRuntime`; isolated `createModels()` does not load every provider/config automatically. `ModelRegistry` is supported, not an obsolete shim; it has no `completeSimple`, so use `streamSimple(...).result()`.
- Jiti maps root pi-ai to the `/compat` superset and can mask invalid root imports. Validate real ESM/types **and** bundled extension loading. Npm `/api/*` exports do not prove Jiti subpath resolution; where the actual host alias misresolves a needed factory, use one explicit supported `/compat` factory, not a custom resolver or root-global routing architecture. Catalog-only `pi-ai/models` began in 0.99.2.
- Runtime dispatch resolves request auth/baseURL/headers/env. Header-only, OAuth and ambient auth may have no API-key string: do not require/extract/echo a key before registry calls. Scope is a selection snapshot, not authorization; empty `ctx.scopedModels` is unrestricted. Preserve explicit evaluation selection/effort and paid-call authority.
- Native setup-abort can return `stopReason: "error"` with an abort message; retain cancellation classification. Provider hooks report failures but dispatch continues, so they are not fail-closed security gates. Auxiliary registry calls do not automatically become session usage: return usage on the outer tool result.
- Preserve `ModelsRequestTransforms` and `ProviderHeaders` null deletion markers. Refresh returns `ModelsRefreshResult`; inspect aborted/errors. Auth mutations establish local consistency, not remote refresh. Propagate OAuth refresh signals; never log credentials.
- `createProvider({ fetchModels })` owns publication; handwritten refresh reads immutable `context.stored` and generation-checked `context.publish({ persist, update })`. Persistence failure prevents paired mutation. Legacy model lists replace catalogs; native providers still receive models.json overlays. Current streams receive `TranscriptContext`: use current system/tool helpers, emit exactly one terminal event, preserve usage, partial-call validity and abort.
- Verify endpoint-specific thinking, limits, replay, deferred tools and pricing. Native codemode uses a fresh restricted VM, not a persistent browser/macOS runtime; 1.0 missing-member reads throw, so use `"name" in tools`, not `typeof tools.name`. Native MCP does not imply parity with SSE, Apps, vault auth, sampling/elicitation or durable capture.

## TUI and removed experimental exports

Use supplied host TUI, never a second terminal/render loop. **Fullscreen is the 1.0 default**; also test regular mode, narrow/wide/CJK, resizing, focus, keyboard/mouse, cancellation, done and disposal. `ctx.hasUI` includes RPC; custom components require `ctx.mode === "tui"`. Use `queryTerminalColors`, not removed `queryTerminalColorScheme`/background query helpers. Extend `CustomEditor` and forward unhandled keys to `super.handleInput`; use configured keybindings. Close custom UI through `done`, not hiding a handle and abandoning its promise.

Agent-core 1.0 removes `AgentHarness`, Session/Storage/repos, durable/harness/node/pico3 exports and uuidv7 re-exports. Its root is Agent/loop/proxy/types. **Ordinary extensions do not need a harness rewrite**: use coding-agent SDK/SessionManager/runtime or stdio RPC. Only explicitly durable requirements warrant evaluating `@earendil-works/pi-durable` and its separate storage contract. Do not promise removed experimental RemoteSession/PiClient exports or convert saved schemas by renaming types.
