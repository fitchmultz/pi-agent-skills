# Version and Distribution Hazards

Verify the exact installed package's exports, emitted types, implementation, and relevant runtime path before copying examples. These source checks cover official **0.87.1** (`f07218c4d4bbc12bef056a7058c3dd49dfe41abe`) and **fitchmultz/pi f1f619c** (`f1f619c0f64b6d0e9756971aac67049c85db63f0`), which also reports 0.87.1. The discovery contract below was subsequently requalified against fork **89c2398** (`89c2398adbf13107b20cb0d312ec412d4d4f1275`); unrelated shared-API checks retain the earlier source baseline. On 2026-09-29, official latest was still 0.87.1; target identity and the native-head context-hook contract were checked against installed fork **9430ac7** (`9430ac72ae93952e211afbf95265b607e570cf93`). This focused follow-up does not requalify the unrelated earlier API checks, every older version, or every platform.

## Shared contracts and fork boundaries

- Both hosts expose `DefaultResourceLoader`, `createAgentSession`, `ModelRuntime`, `agent_settled`, `AgentSession.waitForIdle()`, `ExtensionCommandContext.waitForIdle()`, `ctx.scopedModels`, and replacement `withSession` callbacks. Use these shared APIs for portable features.
- `agent_end` ends one low-level run; retries, compaction retry, and queued continuations can remain. Use final settlement for local-run completion notifications. On the inspected hosts, `agent_before_settle` is the actionable boundary; `agent_settled` is notification-only and defers new work until handlers finish. The fork event can still report detached native obligations in `pendingToolCalls`; do not claim those are complete from local settlement alone. Never substitute low-level `session.agent.waitForIdle()` for session settlement.
- The official host's `/reload` clears the extension source cache; the fork baseline reinitializes cached factories and refreshes resources but requires a **process restart for extension code updates**. Validate the actual distribution's reload/restart path. After `await ctx.reload()`, return without using the old context.
- Fork `ctx.newContext`, native asynchronous tool/result events, extension `recordUsage`, `session_before_auto_compact`, `session_checkpoint`, checkpoint disposal, and restart/recovery additions are absent from the official host. The fork's auto-compaction event includes `retainedToolResultIds`, and its `ContextUsage.source` is required. Verify fork types before use. Public extensions still support both targets; optional fork enhancements must preserve official-host behavior. `pi-posthorse` is the sole fork-only public exception. Do not add no-op shims or block ordinary official workflows on fork APIs.
- `change_dir`, browser tools, question tools, and delegation tools are separate extensions, not core features of either host. Directory overrides affect execution, not the parent's session identity, project settings, trust, AGENTS.md, or loaded skills. Since `pi-subagents` 0.39.0, new delegation resolves the selected execution directory through `pi-change-working-dir` 0.5.0+'s public interface; relative cwd overrides use that directory. Older consumers did not inherit it automatically. Verify the installed pair; use explicit absolute child cwd when targeting a different directory. Ordinary continuation preserves the saved child's directory unless explicitly overridden.
- TUI-only features need `ctx.mode === "tui"`; dialogs can use `ctx.hasUI` in TUI or a servicing RPC client. Print mode cannot answer `ask_question` dialogs. Unsupported UI must not silently grant approval.

## Fork discovery and continuation additions

- Fork `ToolDefinition.discovery` metadata, native `discover_tools`, and `BuildSystemPromptOptions.sectionTools` defer extension-owned integration schemas and full custom instructions on capable native models, not extension execution, safeguards, core instructions, or skills. The former `toolDiscovery` settings inventory has been removed: attach metadata at actual registrations and let the permitted registry derive membership. Official 0.87.1 ignores optional registration metadata and retains ordinary exposure; do not require fork exports or a user-maintained provider/tool list. Read the discovery section in `runtime-authoring-guide.md` before adopting it.
- Fork `registerToolSearch()` is a separate extension API. A sole active callback can become provider-native client `tool_search` on capable Responses routes; multiple callbacks or unsupported routes remain named functions. `discover_tools` itself is an ordinary host loader, not that native search callback, and neither is an MCP extension gateway.
- Fork `live_tool_result` supplies `{ content }` for native WebSocket continuation frames that bypass context hooks. It runs after a finalized result is saved; handlers receive an isolated model-facing copy and compose. It does not change saved results, terminal output, or ordinary requests. Keep `context`/`context_with_system` decoration for ordinary requests; use this additional hook only for the fork's live path.
- Fork `pi update --fork` targets immutable fork installations and pins fetched main before validation/activation. It is not an extension-package updater or an official-host flag. Inspect `docs/cli.md`, the installed help and `FORK.md` before authorized runtime updates; this skill does not authorize running one.

## Context, tools, and event migration

- On the inspected hosts, `SessionManager` is canonical for coding-agent provider context. Mutating `session.agent.state.messages` no longer replaces future request history. Restore with `SessionManager.inMemory(cwd, { id }, entries)`, navigate through the session, or append through the manager and call `session.refreshContext()`.
- `context` receives conversation messages without system messages; Pi restores prompt/tool declarations afterward. Use `context_with_system` for deliberate full-transcript transformations, but do not assume arbitrary changes survive identically on both hosts. Fork 9430ac7 restores the marked native head to index zero and preserves its `nativeHead` marker, timestamp, and initial tool state after each handler; content/section edits remain supported. Already-bound unmarked sessions retain their current window until a native new window/checkpoint. Official 0.87.1 lacks this fork guard: preserve the leading declaration and tools yourself rather than relying on restoration.
- Handle `context_edit` in exhaustive `SessionEntry` switches. Context omission/replacement changes future provider input without erasing raw history, usage, or UI history.
- Current `turn_end` and `agent_before_settle` are actionable boundaries. Use current event/result types and `emitBoundary` when hosting dispatch; do not copy old unions or use ordinary runner `emit` for `turn_end`.
- Migrate removed `shouldStopAfterTurn` to `finishTurn`. Guard error/aborted messages when preserving an old normal-response-only predicate; returning `continue` unconditionally loops.
- The inspected packages bundle TypeBox **1.3.27**. Import `typebox` and inspect its installed APIs; do not pin the former 1.3.7 or restore removed compatibility helpers.
- Tools run in parallel unless a sequential sibling serializes the current native batch. Fork-native asynchronous work from an earlier response can remain detached unless the global mode is sequential. `withFileMutationQueue()` must cover the whole read-modify-write window. Native sequencing does not serialize an explicit external parallel wrapper.
- `{ block: true, terminate: true }` applies to a blocked call. The automatic follow-up is skipped only when every finalized sibling result terminates; result-level `terminate` remains available.
- Committed session replacement and interactive `/tree` abort/persist active work; programmatic navigation rejects while active. Aborting a sequential batch can leave later unstarted siblings unmatched. Wait for final idle when balanced history matters; never invent synthetic tool results.
- `defaultTools` selects startup built-ins while preserving extension/SDK custom tools. Register lazy tools first and activate additively; removals/replacements use fallback. Prompt metadata can still invalidate a cached prefix.
- `pi.sendUserMessage(..., { expandPromptTemplates: true })` requests command/skill/template expansion; default false. Context-only `pi.sendMessage(..., { triggerTurn: false })` must not be used as steering.

## SDK and wire-format traps

- Some SDK prose imports root singleton `getModel`, which is not a pi-ai ESM export. Use `ModelRuntime.getModel()`; `/compat` is for intentional legacy migration. Validate both TypeScript and the real loader.
- SDK inline `Skill`/`PromptTemplate` snippets can show obsolete `source`; use current coding-agent types and examples with `sourceInfo`. Do not confuse these with pi-agent-core harness resource types.
- `SettingsManager.create(cwd, agentDir?, options?)` is positional and requires cwd, not an object overload. `SessionManager.list(cwd)` lists one project; `listAll()` lists normal all-project sessions, and its optional string is a custom session directory.
- JSON/RPC `message_update` is delta-only: no cumulative `message` or event `partial`. Accumulate text/thinking/tool arguments by content index until authoritative `message_end.message`. Top-level cumulative `usage` may stay zero until completion. In-process SDK/extension events are a different contract.
- JSON mode starts with a `SessionHeader` (`type: "session"`). Coding-agent v3 header/entry timestamps are ISO strings; nested message timestamps are numeric milliseconds. Its compaction entries use `firstKeptEntryId`; do not paste a harness schema into that parser.
- RPC `get_commands` exposes `sourceInfo`, not old top-level location/path fields. Parse LF-delimited JSON with incremental UTF-8 decoding and EOF flush, not Node `readline`, which also splits valid Unicode string content.
- RPC `get_available_thinking_levels` returns `{ data: { levels } }`; `RpcClient.getAvailableThinkingLevels()` unwraps it. Derive supported levels from the selected model and re-query after changes; model names and old example lists are not evidence.
- Official `RpcClient.waitForIdle()` waits for a future settlement event; the fork sends `wait_for_idle` and resolves immediately when already idle. Subscribe before prompting or use `promptAndWait()` for portable race-free completion. Fork `collectEvents()` still waits for a future `agent_settled`.
- Direct RPC bash honors `user_bash` and emits `bash_execution_update`. Private output requires raw `excludeFromContext: true`; do not assume every client helper exposes it. Built-in/factory bash injects current `PI_SESSION_ID`, optional `PI_SESSION_FILE`, `PI_PROVIDER`, `PI_MODEL`, and `PI_REASONING_LEVEL`, unless disabled; interactive `!`/`!!` do not. Fork `background_command` bypasses `user_bash` but receives the same session variables unless `exposeSessionEnvironment: false`.
- Message renderers get `{ expanded, outputPad }`; entry renderers get only `{ expanded }`. Persist display-only entries with `appendEntry` plus an entry renderer; use custom messages for model-visible content. Nested model work reports top-level `usage`, not details.

## Provider pitfalls

- pi-ai uses `ModelsRequestTransforms`, not removed `ModelsStreamTransforms`. Preserve `ProviderHeaders` values of `string | null`: null is a deletion marker, not missing data to filter/stringify.
- `ModelRegistry.refresh()` / `ModelRuntime.refresh()` return `ModelsRefreshResult`; inspect abort and provider errors. Runtime-key mutation establishes local state and accepts auth cancellation, not remote freshness; refresh the provider separately when needed.
- Config-form OAuth receives `refreshToken(credentials, signal)` with a concrete signal. Propagate it through every blocking step and do not log credentials.
- `createProvider({ fetchModels })` owns publication. Handwritten refresh reads immutable `context.stored` and uses generation-checked `context.publish({ persist, update })`; never mutate before publication or use removed `context.store`. Persistence failure must prevent the paired state update.
- Native providers still receive `models.json` overlays; legacy `ProviderConfig` differs from models.json and does not accept provider-level `compat`/`modelOverrides`. Check composition order rather than spreading ownership across extensions.
- Root API-factory exports and bundled-loader aliases can differ from prose examples. Check actual exports; `/compat` supplies concrete factories for existing portable integrations. Put request routing/headers on supported model/auth fields and inspect the outgoing request rather than assuming provider metadata is a request default.
- Dynamic providers need a static/stored baseline for cache-only startup. Cache recovery may pass no credential; filtering can receive raw stored/runtime credentials rather than materialized ambient auth. Test offline, refresh, cancellation, persistence, generation, and removal paths.
- `TranscriptContext` carries system prompts and tools in `messages` on current provider streams. Use current helpers such as `getCurrentSystemPrompt()` and `getCurrentTools()`; old separate context fields are obsolete.
- Verify model catalogs, effort maps, pricing, transport, strict-schema/grammar, and deferred-tool capabilities at the actual endpoint. A vendor's maximum context is not necessarily Pi's effective configured cap; API-key and subscription routes need separate validation. Pi async tools/queued steering do not imply provider-side asynchronous tools or mid-generation steering.

## pi-agent-core and remote-host migration

The current root exports `AgentHarness`, `Session`, `Storage`, `SessionRepo`, `JsonlSessionRepo`, and `MemorySessionRepo`. Old `SessionStorage`, `InMemorySessionRepo`, `session.view(lane)`, and blanket `HarnessNotImplemented` scaffold guidance are stale for the inspected sources. Use current Branch/session mutation and Context contracts. Probe the exact operation: `watchSession` still throws `SliceNotImplemented`, which does not imply all execution paths are unavailable.

Custom `FileSystem.renameFile(source, destination, context)` must perform atomic same-filesystem replacement and return failures through `Result`, not throw. Check current signatures rather than copying the old optional-signal API.

Experimental coding-agent client/server surfaces became source-only in 0.85.1. Do not promise a published `RemoteSession`/`PiClient` API from old examples. Prefer the supported local SDK/stdio RPC for normal hosts; explicitly source-targeted remote work must inspect its actual protocol and distinguish durable listing metadata from acquired live state.
