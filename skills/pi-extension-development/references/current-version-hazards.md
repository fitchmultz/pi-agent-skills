# Pi 0.84.2 Current-Version Hazards

Use this file before trusting copied docs/examples. The released implementation and emitted `.d.ts` files win.

- pi-ai exports `ModelsRequestTransforms`; `ModelsStreamTransforms` no longer exists. The transform applies to authenticated stream, deferred-fetch, and deferred-cancel request headers.
- JSON/RPC wire `message_update` contains only `assistantMessageEvent` with its `partial` field removed, plus a top-level cumulative provider-reported `usage` (added in 0.84.2; it may remain zero until completion). Accumulate deltas between `message_start` and `message_end`, then replace local state with authoritative `message_end.message`. In-process SDK and extension `AgentSessionEvent` still includes cumulative `message` and native stream events still carry `partial`; do not erase those distinct contracts.
- `pi.sendUserMessage(content, { expandPromptTemplates: true })` (0.84.2) explicitly dispatches extension commands and expands skills/prompt templates; the default remains `false`. `pi.sendMessage(..., { triggerTurn: false })` records a custom message without steering an active run (fixed in 0.84.2). The `defaultTools` setting (0.84.2) selects the startup built-in tool set globally or per project; extension and SDK custom tools are preserved when it is set.
- `docs/json.md` correctly defines `JsonAgentSessionEvent` and its examples, but its copied base `AgentEvent` union still shows the in-process cumulative `message_update` shape. Use the emitted `JsonAgentSessionEvent` wire type.
- `ModelRegistry.getApiKeyAndHeaders()` returns a discriminated result whose successful `headers` are `ProviderHeaders` with `string | null` values. Inspecting code handles `null`; forwarding code passes deletion markers through unchanged instead of filtering or stringifying them.
- `ModelRegistry.refresh(options?: ModelsRefreshOptions)` and `ModelRuntime.refresh()` return `ModelsRefreshResult`. Check `aborted` and every provider entry in `errors`; awaiting alone does not mean all providers refreshed.
- `ModelRuntime.setRuntimeApiKey(providerId, key, options?: AuthOperationOptions)` accepts only auth cancellation, synchronizes cached/local state, and does not wait for remote freshness. Call `refresh({ providers: [providerId], signal })` separately when current remote models are required.
- Config-form OAuth requires `refreshToken(credentials, signal: AbortSignal)` and the callback must pass or check the concrete signal for every blocking operation.
- Handwritten native `Provider.refreshModels()` receives read-only `context.stored` plus generation-checked `context.publish()`. It must not mutate current models before a successful publication or use removed `context.store`. `publish` omits persistence when `persist` is absent, writes a `ModelsStoreEntry` when present, and deletes it with `persist: null`.
- `createProvider({ fetchModels })` needs no manual publication migration: return fetched models and let the factory restore, persist, and publish them. Config-form `refreshModels` callbacks that only return models also remain unchanged; only custom persistence uses `context.stored`/`context.publish()`.
- A failed persistence mutation prevents the paired synchronous update. Test generation supersession, abort, persistence failure, fetch failure, cached/offline restoration, and successful network publication separately.
- pi-agent-core's current harness uses the v4 lane-based `Session`, `SessionStorage`, and `SessionRepo` contracts with shared sequence numbers, durable operation records, global facts, and lane views. The coding-agent v3 `SessionManager`/JSONL format is a different surface.
- pi-agent-core v2 `AgentHarness` and session exports now come from `@earendil-works/pi-agent-core`; removed experimental subpaths and legacy JSONL/in-memory repository APIs are not compatibility options. Use root-exported v4 `JsonlSessionRepo` or `InMemorySessionRepo` implementing `SessionRepo`. Promotion does not mean execution completeness: current prompt, queue, compaction, navigation, resume, watch, lane-management, and manual-drive paths reject with `HarnessNotImplemented`.
- Custom harness `FileSystem` implementations must implement `renameFile(source, destination, signal?)` as atomic same-filesystem rename with replacement, returning failures through `Result` instead of throwing. `JsonlSessionRepoFileSystem` includes it for staged publication and repair.
- `RemoteSession.sessions` and `PiClient.snapshot?.sessions` expose durable `SessionMetadata` only. Runtime `phase`, `model`, `thinkingLevel`, `attached`, and `locked` belong to an acquired `SessionSnapshot`.
- `docs/sdk.md`, create-session JSDoc, and `examples/sdk/README.md` still import singleton `getModel` from the pi-ai root, where it is not exported. Use `ModelRuntime.getModel()` for current SDK code or `/compat` only while migrating legacy singleton code.
- `docs/sdk.md` inline `Skill` and `PromptTemplate` objects use obsolete `source` fields and omit required current fields. Follow emitted types plus the shipped skills and prompt-template examples, which use `sourceInfo`.
- `docs/sdk.md` still shows `SettingsManager.create()` without the required `cwd`; the emitted file-backed signature is positional: `SettingsManager.create(cwd, agentDir?, options?)`. There is no `create({ cwd, ... })` overload.
- `docs/sdk.md` says `SessionManager.listAll(cwd)`, but the argument is a custom sessions directory. Use `list(cwd)` for one project or parameterless `listAll()` for the normal all-project tree.
- Pi 0.84.2 bundles TypeBox 1.3.7. Import from `typebox` and use its current APIs; do not pin an older copy or restore removed TypeBox compatibility helpers.
- Extension contexts expose the session's read-only resolved model scope as `ctx.scopedModels`. A non-empty array mirrors `--models`/`enabledModels`; an empty array means no scope is configured and all available models remain eligible.
- `docs/sdk.md` still contains stale comments around `session.agent.waitForIdle()`. Use `AgentSession.waitForIdle()` or `promptAndWait()` for final settlement. Low-level `Agent.reset()` now rejects until the agent is idle (0.84.1).
- `docs/custom-provider.md` describes native provider registration but its legacy `ProviderConfig` reference omits `refreshModels`; the emitted extension config includes it. That legacy shape still does not support provider-level `compat` or `modelOverrides`.
- Native provider-level `baseUrl` and `headers` are not reliable request defaults. Put routing/static headers on models or return them from auth resolution, then probe the outgoing request.
- Native-provider docs import concrete API factories from the pi-ai root, but the root declaration does not export them. Import `createProvider` and auth helpers from the root and concrete factories such as `openAICompletionsApi` from `/compat`; validate both TypeScript and the bundled extension loader.
- Cache-only recovery may call provider refresh with `credential: undefined`. `filterModels(models, credential)` also receives raw stored/runtime credentials, not materialized ambient auth.
- `/reload` re-runs factories but does not automatically prune a removed or renamed conditional provider. Explicitly unregister it or rebuild the runtime when testing removal.
- Committed session replacement and the interactive `/tree` command abort and persist active work; programmatic `navigateTree()` (extension `ctx.navigateTree`, RPC, print mode) rejects while a run is active. Only the aborting paths can leave later unstarted siblings in a sequential tool batch unmatched. Wait for final idle when balanced history is required; do not append synthetic aborts or tool results.
- Interactive and RPC startup restore cached catalogs then refresh in the background. Print mode, `--list-models`, and most SDK construction stay cache-only unless the caller explicitly refreshes. Dynamic providers need a static or stored baseline.
- Generated catalogs expose only provider-verified effort levels. For example, current `qwen-token-plan/qwen3.8-max` rejects `minimal`, `high`, and `max` despite its name; derive levels from metadata or `get_available_thinking_levels`. Qwen Token Plan also registers `qwen-token-plan-individual` (0.84.1), sharing `QWEN_TOKEN_PLAN_API_KEY`.
- Raw RPC `get_available_thinking_levels` returns `{ data: { levels } }`; `RpcClient.getAvailableThinkingLevels()` unwraps it. Query again after model changes.
- `examples/sdk/README.md` names nonexistent `08-slash-commands.ts`, describes the thinking default as `off`, and only lists four levels. The shipped file is `08-prompt-templates.ts`; runtime defaults to `medium`, and the global vocabulary also includes `minimal`, `xhigh`, and `max`, subject to the model map.
- Extension declaration JSDoc still shows `refreshToken(credentials)` even though the emitted config-form OAuth signature requires `refreshToken(credentials, signal)`.
- `docs/json.md` still omits several current event variants from its copied base union. JSON mode also emits a leading `SessionHeader` with `type: "session"`; discriminate it from later events.
- `docs/rpc.md` still shows stale top-level `location`/`path` command provenance. Read canonical `sourceInfo` (`path`, `source`, `scope`, `origin`, optional `baseDir`).
- `examples/rpc-extension-ui.ts` still uses Node `readline` even though `docs/rpc.md` rejects it. Use incremental UTF-8 decoding, LF splitting, optional trailing-CR trimming, and explicit EOF flush.
- Pi can persist top-level `usage` on `ToolResultMessage`, compaction, and branch summaries. `AgentSession.getSessionStats()` includes all three across the session tree.
- `docs/session-format.md` mixes harness `retainedTail` with coding-agent JSONL. Coding-agent `CompactionEntry` still requires `firstKeptEntryId`; do not copy harness v4 schemas into coding-agent parsers. Persisted coding-agent v3 header/entry timestamps are ISO strings while nested message timestamps are numeric milliseconds.
- Extension tools may set `constrainedSampling`; gate strict JSON Schema or OpenAI grammar modes on current model capabilities. `require` fails closed while `prefer` and grammar configurations can fall back.
- Blocked `tool_call` handlers may return `{ block: true, terminate: true }` (0.84.1). Termination applies to the blocked call; the automatic follow-up model call is skipped only when every finalized result in the sibling batch terminates. Result-level `terminate` remains the structured-output mechanism.
- Built-in and `createBashTool()`/`createBashToolDefinition()` bash injects `PI_SESSION_ID`, `PI_SESSION_FILE` when persisted, `PI_PROVIDER`, `PI_MODEL`, `PI_REASONING_LEVEL`; `exposeSessionEnvironment: false` disables injection and inherited values, and user-entered `!`/`!!` commands never receive them. CLI/RPC child processes set both `AI_AGENT=pi` and `PI_CODING_AGENT=true`; SDK embedding sets neither automatically.
- Message renderers receive `{ expanded, outputPad }`; entry renderers receive only `{ expanded }`. Ctrl+X remains reserved for `app.message.copy`.
