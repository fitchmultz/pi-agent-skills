# Pi 0.82.0 Current-Version Hazards

Use this file before trusting copied docs/examples. The active installed source and emitted `.d.ts` files win.

- `docs/sdk.md` still shows `SettingsManager.create()` without the required `cwd`; the emitted signature requires `SettingsManager.create(cwd, ...)` or `create({ cwd, ... })`.
- `docs/sdk.md` says `SessionManager.listAll(cwd)`, but the argument is a custom sessions directory. Use `list(cwd)` for one project or parameterless `listAll()` for the normal all-project tree.
- `docs/sdk.md` still contains stale comments around `session.agent.waitForIdle()`. Use `AgentSession.waitForIdle()` or `promptAndWait()` for final settlement.
- `docs/custom-provider.md` describes native provider registration but its legacy `ProviderConfig` reference omits `refreshModels`; the active `ProviderConfig` type includes it. That legacy shape still does not support provider-level `compat` or `modelOverrides`.
- The native-provider quick example relies on provider `baseUrl`, and the native `Provider` type also exposes `headers`, but Pi 0.82.0 does not apply either as request defaults. Put request routing/default headers on models or return them from auth resolution, then probe the outgoing request.
- The native-provider docs import concrete API factories from the pi-ai root, but root types do not export them. Import `createProvider` and auth helpers from `@earendil-works/pi-ai` and factories such as `openAICompletionsApi` from `/compat`. Package-based Node installs may resolve `/api/*`, but the bundled extension loader does not expose those virtual subpaths reliably. Validate both TypeScript and real target loading.
- Cache-only/offline recovery may call provider refresh with `credential: undefined`, as the active optional type permits. Handle that path and avoid network work when `allowNetwork` is false.
- Native `filterModels(models, credential)` receives the raw runtime credential-store result, which may be a non-persistent runtime API-key override or persisted credential. Ambient/env auth is not materialized there, so it may still receive `undefined` when ambient auth is configured.
- `/reload` re-runs extension factories. Same-id native registration discards prior legacy state and replaces prior native ownership; switching back deletes native ownership and starts from the new legacy fragment, while only subsequent legacy re-registrations merge defined fields. A removed or renamed provider in either form can remain in the live `ModelRuntime`; explicitly unregister it or rebuild the runtime when testing conditional removal.
- Interactive and RPC startup restore cached catalogs first and refresh model catalogs in the background. Interactive footer provider counts read the current snapshot and do not wait on that refresh. `/model` and the model picker call `modelRuntime.refresh()`, which reloads `models.json` then refreshes catalogs. Print mode, `--list-models`, and most SDK construction stay cache-only unless the caller explicitly refreshes. Do not use a network-only dynamic catalog as the sole startup source.
- Direct Kimi K3 routes remain `kimi-coding/k3`, `moonshotai/kimi-k3`, and `moonshotai-cn/kimi-k3` with `low`, `high`, and `max`. Moonshot routes use OpenAI Completions with `thinkingFormat: "openai"`, `supportsReasoningEffort: true`, and `deferredToolsMode: "kimi"`; Kimi Coding still uses Anthropic compatibility and empty-signature replay.
- Generated catalogs now expose only provider-verified reasoning-effort levels. A model id containing `max` still does not imply the `max` thinking level. For example, `qwen-token-plan/qwen3.7-max` exposes `off` through `high`; derive levels from model metadata or RPC `get_available_thinking_levels`.
- RPC `get_available_thinking_levels` returns raw `{ data: { levels } }`; bundled `RpcClient.getAvailableThinkingLevels()` unwraps that to `ThinkingLevel[]`. Query again after model changes.
- `examples/sdk/README.md` still describes the thinking default as `off` and lists only `off`/`low`/`medium`/`high`; the runtime default is `medium`, and the global vocabulary also includes `minimal`, `xhigh`, and `max`, subject to the current model's map.
- `docs/json.md` documents summarization retry events but still omits several current `AgentSessionEvent` variants, including `agent_settled`, `entry_appended`, `session_info_changed`, `thinking_level_changed`, and `bash_execution_update`, plus `agent_end.willRetry`. Compaction and branch-summary provider failures emit `summarization_retry_*` under the configured retry policy. JSON mode also emits a leading `SessionHeader` with `type: "session"`; discriminate it from later events.
- `docs/rpc.md` still shows stale top-level `location`/`path` command provenance. Read canonical `sourceInfo` (`path`, `source`, `scope`, `origin`, optional `baseDir`).
- `examples/rpc-extension-ui.ts` still uses Node `readline` even though `docs/rpc.md` rejects it. `readline` accepts CR and Unicode line separators beyond Pi's LF-only framing; use incremental UTF-8 decoding, LF splitting, optional trailing-CR trimming, and explicit EOF flush.
- Pi 0.82.0 can persist top-level `usage` on `ToolResultMessage`, `compaction`, and `branch_summary`. `AgentSession.getSessionStats()` includes all three across the full session tree; parsers that inspect only assistant messages undercount tokens and cost.
- `docs/session-format.md` describes harness `retainedTail`, but the coding-agent `CompactionEntry` still requires `firstKeptEntryId` and has no `retainedTail`. Do not copy the harness schema into coding-agent session parsers.
- `docs/session-format.md` still mixes numeric and ISO entry timestamps. Persisted v3 header/entry timestamps are ISO strings; nested message timestamps remain numeric milliseconds.
- Extension tools may set `constrainedSampling` (`json_schema` prefer/require or OpenAI Lark/regex grammar). Gate on model `compat.supportsStrictMode` / `supportsStrictTools` / `supportsOpenAIGrammarTools`; `require` fails closed when unsupported, while `prefer` and grammar configs fall back.
- OpenRouter and Kimi Coding now support `/login` OAuth (`Sign in with OpenRouter`, `Sign in with Kimi Code`) in addition to API keys. Prefer the login path over hand-written keys when testing those providers.
- Built-in/factory bash injects `PI_SESSION_ID`, `PI_SESSION_FILE` (persisted sessions only), `PI_PROVIDER`, `PI_MODEL`, and `PI_REASONING_LEVEL` at command start. RPC bash can stream `bash_execution_update` deltas with an optional request `id`.
- llama.cpp loaded models use the server-reported context window for both `contextWindow` and `maxTokens` instead of a 16K output cap.
- Ctrl+X remains the reserved default `app.message.copy` shortcut and is not delivered to custom editor input; choose a different editor chord.
