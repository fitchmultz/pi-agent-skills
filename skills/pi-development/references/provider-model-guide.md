# Provider and Model Guide

Use for provider registration, auth, dynamic catalogs, model metadata, or SDK model-runtime work. Read installed `docs/providers.md`, `docs/custom-provider.md`, `docs/models.md`, and current pi-ai/Pi types first; read `docs/llama-cpp.md` for local llama.cpp workflows.

## Choose the smallest provider mechanism

1. Use `models.json` for endpoint/model configuration that needs no runtime code.
2. Use legacy `pi.registerProvider(id, config)` for supported APIs, static/simple dynamic catalogs, or legacy OAuth/`streamSimple` integration.
3. Use `pi.registerProvider(createProvider(...))` when the provider owns native auth, credential filtering, catalog caching, or stream behavior.
4. Hand-build a complete `Provider` only when `createProvider` cannot express the needed refresh/store semantics.

`models.json` composes above native providers. With legacy config, extension fields can win while `modelOverrides` still apply last; inspect the active composer for precedence-sensitive fields. Never spread provider ownership across extensions unless the merge/replace order is intentional and tested.

## Full provider extensions

- Import `createProvider`, auth helpers, and types from the `pi-ai` root. Root types do not export concrete API factories, despite the current native-provider docs; import factories such as `openAICompletionsApi` from `@earendil-works/pi-ai/compat`. Native npm supports `/api/*`, but Pi's Jiti aliases can misresolve subpaths. Qualify the real bundled loader and shipped module form; where needed, keep one explicit supported `/compat` factory. Native physical peers are not unconditionally replaced by Jiti mappings; see [Native extension module loading](runtime-authoring-guide.md#native-extension-module-loading). Do not build a custom resolver or rely on root globals masked by Jiti.
- A complete `Provider` owns `id`, `name`, auth, synchronous `getModels()`, optional `refreshModels`/`filterModels`, and both `stream` and `streamSimple`. Registering it discards any same-id legacy state and replaces any prior native provider; switching back deletes native ownership and starts a fresh legacy config. Only later legacy re-registrations merge defined fields.
- `createProvider({ models, fetchModels })` restores and persists the dynamic overlay through Pi's `ModelsStore`, preserves the prior list when fetching fails, supersedes/aborts older provider generations, and owns serialized generation-checked publication. Return fetched models; do not add manual publication code. A persistence failure prevents the paired in-memory update, so validate fetch and persistence failures separately. The callback receives the canonical credential/stored/publish/network/force/signal context.
- Dynamic providers need a static or stored baseline: interactive and RPC modes restore cached catalogs and then refresh in the background; print mode, `--list-models`, and default SDK construction do not automatically perform network refresh. `/model` and the model picker call `modelRuntime.refresh()`, which reloads `models.json` before catalog refresh.
- Handwritten `refreshModels` implementations read the immutable `context.stored` snapshot and publish persistence plus synchronous catalog mutation through `await context.publish({ persist, update })`. Never mutate first or use removed `context.store`. Omit `persist` to leave storage unchanged, pass a `ModelsStoreEntry` to write, or pass `null` to delete. Stop if publication returns `false` because a newer generation won.
- Honor `allowNetwork` and the concrete `signal`; treat `force` as an explicit freshness request. Cache-only recovery may pass `credential: undefined`. Config-form callbacks that only return models remain unchanged; only custom persistence uses `stored`/`publish`.
- `filterModels(models, credential)` filters after auth is considered configured, but receives the raw runtime credential-store result, including a runtime API-key override when present. Do not assume ambient/env credentials are materialized in that argument.
- Do not assume native provider-level `baseUrl` and `headers` are request defaults. Put `baseUrl`/static headers on each model or return headers from auth resolution, then inspect a real or stubbed request.
- Current streams receive `TranscriptContext`: read system prompts/tool declarations from messages using the current helpers, not old separate context fields. Emit well-formed event sequences, exactly one terminal event, observe abort, preserve metadata, accumulate text/thinking/tool-call deltas, and honor option callbacks. Prefer the bundled API factories over reimplementing a wire protocol.
- Stream tool-call arguments with pi-ai's `ToolCallArgumentsStream`: keep one per open block in a map keyed by the provider's block index, set `block.arguments = stream.append(delta)` for each delta, and finish with `Object.assign(block, stream.finish())`, which parses the complete text once and reports malformed input in `argumentsError`. A provider that resends the complete argument text calls `stream.replace(text)`, which returns the new `delta` and the partial `arguments`. Keep raw JSON text, provider indices and other stream state off the content blocks so they never reach partial messages or transcripts; do not re-parse accumulated `partialJson`. Both classes come from the `pi-ai` root; `StreamingJsonParser.append()` returns `JsonChange`s for other incremental JSON. Grammar (custom) tool input uses `appendGrammarToolInputJsonDelta()` from the `/api/constrained-sampling` subpath (see the loader note in `current-version-hazards.md`): it takes each new delta, and `closeGrammarToolInputJson()` closes the input at the end. See the official `custom-provider-anthropic` example.
- Set `usage.cost.totalFromProvider: true` only when `total` is the provider's billed amount; missing or `false` marks a catalog estimate. Set the assistant message's `responseModel` when the provider reports the concrete model behind the requested one. A device-code login can set `openBrowserOnConfirm: false` or `copyCodeOnConfirm: false` on `OAuthDeviceCodeInfo` to stop clients offering those actions (both default to `true`).
- `/reload` clears factory caches and reinitializes providers on both hosts. On a reload-capable path, removing or renaming conditional registration does not by itself prove the old live provider was pruned. Explicitly unregister it or rebuild the runtime when validating removal.

## Auth and model-runtime rules

- `ModelRuntime` is the canonical async model/auth facade. Create one runtime, pass it to `createAgentSession`, and inject a pi-ai `CredentialStore` such as `InMemoryCredentialStore` for isolated tests. Extension code still uses synchronous `ctx.modelRegistry`; await `modelRegistry.refresh()` before reads that depend on fresh dynamic catalogs.
- Extension model selectors and actions that must mirror the current session scope should read the read-only `ctx.scopedModels` snapshot. Use its models and optional thinking levels when non-empty; an empty array means `--models`/`enabledModels` did not constrain the session, so fall back to all available models.
- Current pi-ai root exports omit the removed singleton `getModel`/`getModels`/`getProviders`/`stream` API. New SDK code should use `createModels`/provider factories, and Pi extensions should prefer `ctx.modelRegistry` plus `pi.registerProvider`. Use `/compat` for old singleton migration and, until the export/loader mismatch is fixed, the concrete lazy API factories needed by full provider extensions.
- Never import removed pi-ai `/base` entrypoints. Type-check the actual package before trusting examples.
- Preserve credential precedence deliberately: explicit per-request API-key override → runtime API-key override → stored credential → configured legacy/models.json key or command → inherited/native ambient resolver. A stored credential owns the provider, so failed/unsupported stored auth does not silently fall back to environment auth. Read stored credentials directly only for one-off inspection; request auth comes from `ModelRuntime.getAuth()` or provider-owned auth.
- `pi auth check` preflights provider or model credentials from the CLI and can print the resolved credential via `--credentials`; treat that output as a secret and never capture it in logs, transcripts, or artifacts.
- `ModelRegistry.refresh(options?: ModelsRefreshOptions)` and `ModelRuntime.refresh()` return `ModelsRefreshResult`; inspect `aborted` and each provider error rather than treating a resolved promise as universal success.
- `setRuntimeApiKey(providerId, key, { signal })` and `removeRuntimeApiKey(providerId, { signal })` are async auth mutations. Await and handle `CredentialSynchronizationError`. They make cached/local state consistent but do not wait for remote freshness; call `refresh({ providers: [providerId], signal })` separately when required.
- `auth.json` provider entries may include provider-scoped `env`; Pi applies these for in-process provider resolution/streaming. Do not log or persist resolved values elsewhere.
- Prefer registry stream/complete dispatch, which resolves request-time auth: don't require/extract/echo a nonempty API key (OAuth/header-only/ambient auth can be keyless). Keep returned-error and setup-abort classification; auxiliary calls report top-level tool usage. When explicit auth inspection is required, `ModelRegistry.getApiKeyAndHeaders()` results carry `ProviderHeaders`, whose values are `string | null`. Preserve null deletion markers unchanged when passing headers to `ModelRuntime`/pi-ai request options; do not filter, stringify, or spread them into a `Record<string, string>` assumption.
- Config-form OAuth `refreshToken(credentials, signal: AbortSignal)` must accept the concrete signal and propagate it to refresh fetches, locks, sleeps, and polling.
- Env indirection is explicit: uppercase header/key values are literals unless prefixed with `$`; `${VAR}` and leading `!command` are supported where current config types/docs say so. `$$` and `$!` escape literal prefixes.
- `envApiKeyAuth` checks stored API-key credentials before environment variables. Build keyless/ambient auth only with an explicit resolver that reports configuration truthfully.
- OpenRouter and Kimi Coding support both API-key env auth and `/login` OAuth (`Sign in with OpenRouter` mints a user-controlled key; `Sign in with Kimi Code` uses device auth with refresh). Prefer login flows for interactive setup.
- In non-interactive mode, fail closed when auth is missing; never prompt or invent fallback credentials.

## Model metadata and compatibility

- Current built-in API literals are `openai-completions`, `mistral-conversations`, `openai-responses`, `azure-openai-responses`, `openai-codex-responses`, `anthropic-messages`, `bedrock-converse-stream`, `google-generative-ai`, `google-vertex`, and `pi-messages`. `Api` also permits custom strings; use exact current types and a real stream implementation.
- Treat `api`, `reasoning`, `input`, `compat`, `thinkingLevelMap`, `contextWindow`, `maxTokens`, `cost`, and optional `cost.tiers` as runtime behavior. Never guess them from model names.
- Both hosts publish `schemas/models.schema.json` and require supplied `contextWindow`/`maxTokens` in definitions or overrides to be positive numbers, not zero-as-unlimited. Omit unknown optional limits or use verified values. Validation also enforces positive integer image dimensions/byte/count limits (JPEG quality 1–100) and positive supplied prompt-cache lifetimes.
- Thinking levels are `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, and `max`, but generated catalogs expose only provider-verified effort levels and each model still has only its mapped subset. Query `getSupportedThinkingLevels(model)` in SDK code or RPC `get_available_thinking_levels` after model changes.
- Direct Kimi K3-family routes (`kimi-coding/k3`, `kimi-coding/k3.1-pro`, `moonshotai/kimi-k3`, `moonshotai/kimi-k3.1-pro` and their `moonshotai-cn` counterparts) expose `low`, `high`, and `max`. Kimi Coding (`https://api.kimi.com/coding/v1`) and Moonshot both use OpenAI Chat Completions with `thinkingFormat: "openai"`, `supportsReasoningEffort: true`, `requiresReasoningContentOnAssistantMessages: true`, and mid-conversation system/tool-addition support. Copy each route's base URL, auth and pricing from the active catalog; `models.json` base-URL overrides for `kimi-coding` include `/v1`.
- Qwen Token Plan registers `qwen-token-plan`, `qwen-token-plan-cn`, `qwen-token-plan-individual`, and `qwen-token-plan-individual-cn`. Credentials depend on the host, region and plan; the fork prefers a matching per-plan variable before the shared regional fallback, while official Pi uses the shared variables or explicit native configuration. Use the [Qwen credential mapping](#qwen-credentials-and-catalogs). Model names do not imply thinking support: current `qwen3.8-max` maps `low`, `medium`, and `xhigh`, while explicitly rejecting `off`, `minimal`, `high`, and `max`. Verify current catalog metadata instead of freezing a count.
- Built-in catalogs also include `google` (`gemini-3.1-pro-preview`, `gemini-3-flash-preview`, `gemini-2.5-pro`, `gemini-2.5-flash` via `GEMINI_API_KEY`) and `minimax-cn`, plus `cloudflare-workers-ai` classifiers `@cf/cloudflare/clef`, `@cf/cloudflare/clef-omni` (also `cloudflare/clef-omni` on OpenRouter), and `@cf/cloudflare/clef-flash` with `["text", "image"]` input support in `models.classify`. Always inspect the active latest host's generated catalog for newer models and providers.
- Pi loads llama.cpp as a hidden built-in. `/login llama.cpp` stores router URL/optional key; `/llama` manages loading. Discovery is live and non-persistent. Current selection includes loaded models, sleeping models, and autoloadable unloaded presets; do not restore a loaded-only filter from old guidance. Read server-derived model limits and the current manager rather than adding a duplicate provider or shell mutation during discovery.
- Each `cost.tiers` item must define `inputTokensAbove` and all four rates. Pi selects the highest strictly exceeded threshold from request-wide input plus cache read/write; ordinary cache writes use tier `cacheWrite`, while `cacheWrite1h` uses twice tier input.
- Current OpenAI-compatible thinking formats are `openai`, `openrouter`, `deepseek`, `together`, `baseten`, `zai`, `qwen`, `chat-template`, `qwen-chat-template`, `string-thinking`, and `ant-ling`. Use `chatTemplateKwargs` for `chat-template` and `chatTemplateArgs` for `baseten`; do not rewrite request payloads ad hoc.
- Current session affinity uses `sessionAffinityFormat`: `openai`, `openai-nosession`, or `openrouter`. It does not disable `prompt_cache_key`; do not restore removed `sendSessionIdHeader` flags.
- `compat.promptCacheKeyMode` is `"auto"`, `"enabled"`, or `"disabled"`. For Completions, `auto` sends the cache key to OpenAI or a route with long retention enabled; `enabled` sends it whenever caching is active. Responses `auto` and `enabled` both send it when caching is active. `disabled` suppresses it. Inspect the endpoint before you set it.
- Completions requests omit `tools` when no tools are active, even with tool history. Set `compat.requiresToolsWithToolHistory: true` only for a proxy that requires the empty array. `requiresNonNullAssistantContent` separately changes textless assistant replay from `null` to `""`. Do not add payload-rewriting hooks for behavior covered by these native flags.
- Anthropic threads require a `sessionId` and caching. Official Pi defaults them on only for provider `anthropic` when `baseUrl.includes("api.anthropic.com")`; the fork's upstream-ahead implementation removes the provider-ID condition. This substring test is not a hostname security check. Explicit `compat.supportsMessageThreads` wins on both: set it for a verified custom route when the official default is insufficient. Let Pi own continuation and full-request fallback. On the fork, a request asking for or carrying a provider summary block sends no message thread. Auxiliary requests that repeat earlier input use `disableContinuation`, and standalone owners call `cleanupSessionResources(sessionId)` when the session ends, passing the ID actually used in provider requests. A copied fork session can use an inherited cache identity rather than its own `AgentSession.sessionId`; managed disposal already performs that cleanup.
- `OpenAICompletionsOptions.toolChoice` is a stream option, not model `compat`. Preserve its typed union: `"auto"`, `"none"`, `"required"`, or a named function object.
- Tool `constrainedSampling` is model-gated: `json_schema` + `strict: "prefer"|"require"` needs `compat.supportsStrictMode`/`supportsStrictTools` on the active path; OpenAI Lark/regex grammar needs `compat.supportsOpenAIGrammarTools`. Prefer falls back; require fails closed; grammar falls back when unsupported. Use explicitly typed schemas for portability, and distinguish the [upstream-ahead schema conversion](#upstream-ahead-provider-contracts) from the fork's retained Claude budgets.
- Enable deferred tools only with endpoint proof: Anthropic references require `supportsMidConvoSystemMessages` plus `supportsMidConvoToolChanges`, OpenAI Responses search requires `supportsToolSearch`, and compatible Kimi Chat Completions require `supportsMidConvoSystemMessages` plus `supportsMidConvoToolAdditions`. Activate tools additively and validate immediate next-turn definitions.

The [OpenAI latest-model guide](https://developers.openai.com/api/docs/guides/latest-model) describes vendor API capabilities, not automatic Pi support. Verify model/endpoint, transport, accepted reasoning parameters, and Pi serialization before adopting async tools, WebSocket steering, reasoning configuration updates, or cache controls. API-key, subscription, and proxy routes may differ. Preserve the host's selected model/effort; this skill must not create a second model router or blindly copy vendor request examples.

Optional tools use native deferred exposure with `tool_search` on both hosts; instruction groups no longer exist. Native tool_search, provider-native search and gateway composition have different contracts. Read `runtime-authoring-guide.md` before changing exposure or instruction gates; native codemode/deferred tools are callable even when inactive.

### Other provider differences

- **Google transport:** the fork forwards a custom `fetch` to Google Generative AI and Vertex inference requests. Vertex ADC token acquisition still uses the Google auth library's own HTTP client, so this is not interception of all Google traffic. The SDK's automatic continuation is off; a CONTINUATION finish becomes `stopReason: "length"`. Official Pi rejects an injected Google fetch: use its native transport and supported routing/headers/hooks when sufficient, or report that specific official-host blocker if per-request custom transport is indispensable. Never silently change the Gemini protocol or global transport.
- **Schema conversion:** the fork's upstream converter rejects untyped strict-schema nodes such as `items: {}`, `Type.Unknown()`, `Type.Any()` or a bare `const`: `prefer` falls back to non-strict and `require` fails locally. Enum-only nodes remain supported. Official Pi needs explicitly typed portable schemas; do not assume it performs this local fallback. The fork also retains root `additionalProperties` in non-strict Anthropic requests, while official Pi omits it on that wire path. Preserve strict local argument validation on both, and use a supported strict-sampling path when that restriction must be represented on the wire.
- **Transport retries:** the fork recognizes additional connection-closed and bare socket errors within the existing retry budget. Official Pi can return an unclassified terminal error. Surface it honestly; an owner-controlled retry, when required, must be bounded, abort-aware and use unchanged input. Do not fabricate error strings to trigger native retries.
- **llama.cpp:** the fork's default server port is 9931; official Pi's is 8080. Stored and explicitly configured URLs remain authoritative. Use native `/login llama.cpp` or `LLAMA_BASE_URL` for the actual server, and do not rewrite a working endpoint merely to match the default.

The fork's current upstream-sync record mentions `modelOverrides.enabled`, but the frozen types, schema and composer do not implement that field. Do not use it. The existing fork-only `modelOverrides.hidden` behavior remains unchanged.

## Fork provider differences

These are retained fork capabilities in the pinned `FORK.md`, not promises about official Pi. Check `packages/ai/src/api/{strict-tool-limits,anthropic-messages,bedrock-converse-stream,google-shared,kimi}.ts` and the selected host's catalog/composer.

- **Claude strict tools:** the fork budgets 20 strict definitions and 16 union-typed parameters per request for Anthropic and Bedrock Claude. Anthropic counts initial and inline definitions together. Required definitions reserve their shares first; preferred definitions then compete in declaration order, and those that do not fit are non-strict. Required definitions are never silently downgraded; required tools alone over the counted limits fail before sending. Other Bedrock models do not receive this budget. The native rejection fallback remains for limits a count cannot predict, such as compiled grammar size. On official Pi, use the same `constrainedSampling` API: `prefer` unless the contract requires failure without strict sampling. Anthropic/Bedrock retry a recognized pre-stream strict-limit rejection with preferred tools non-strict and remember it for the session; required tools stay strict. If rejection-free strict requests are necessary, supply definitions within those limits yourself. Standalone owners call `cleanupSessionResources(sessionId)` on both hosts, using the provider-request identity rather than assuming it equals the copied session's own ID.
- **Gemini unsigned replay:** both hosts retain valid base64 thought signatures only for the same provider and model. The fork also marks the first function call of a message whose calls are all unsigned with `skip_thought_signature_validator`<!-- fork-only -->. It applies only to `api: "google-generative-ai"` with provider `google` (including its gateway route), an empty base URL, or exact URL hostname `generativelanguage.googleapis.com`. Parsed Gemini versions below 3 and IDs starting `deep-research-` are excluded; unknown-version aliases pass the version guard. It leaves Vertex, OpenCode/OpenCode Go and other-host custom providers unchanged, and keeps previous-turn serialization stable. On official Pi, preserve native signatures and finish the originating model's tool turn before switching to Gemini, or start a new session for it. Do not inject the marker indiscriminately into Google routes. The source records live verification through a `google` gateway to the Gemini API, not a separate direct-host request; this refresh made no live request.
- **Gemini tier estimates:** for `google-generative-ai` with provider `google`, an empty base URL or exact parsed hostname `generativelanguage.googleapis.com`, the fork uses the confirmed streamed tier for known text-model input, output and cache-read estimates, including Priority downgrades. A requested tier does not prove delivery. Token counts, unknown IDs/tiers, unqualified custom routes and Vertex retain their prior behavior. Official Pi retains catalog estimates: label them accordingly, or derive a separate estimate from observed returned tier and verified prices without calling it provider-billed cost. There is no new public pricing option to invent. Source: `packages/ai/src/api/google-shared.ts`.
- **Gemini tool-generation retries:** the fork recognizes error replies with `rawStopReason` of `MALFORMED_FUNCTION_CALL` or `UNEXPECTED_TOOL_CALL`, or bounded matching gateway error text, within the configured retry budget. Do not infer that safety refusals, excessive-tool-call stops, aborts or arbitrary finish reasons are retryable. Official Pi can return these as terminal errors; preserve that result and use an explicit bounded, abort-aware owner-controlled retry only when required. The retry helpers are shared APIs; their recognized classifications differ. Source: `packages/ai/src/utils/retry.ts`.
- **Kimi cache-write estimates:** for canonical Kimi Coding/Moonshot/Moonshot China K3-family OpenAI Completions chat entries, the fork restores zero `cost.cacheWrite` to the entry's own `cost.input` during hydration and remote overlays. Nonzero rates, other IDs/APIs and custom endpoints stay unchanged. Kimi Coding's implied K3.1 Pro/Highspeed estimates use $2/$4 per million tokens; do not apply those USD literals to China entries with their own input rates. These are estimates, not subscription invoices. Official Pi lacks the restoration; when accurate estimates matter, supply verified `cost.cacheWrite` per exact provider/model through native `models.json` `modelOverrides`, preserving other metadata. Both hosts' native Kimi protocol and thinking contracts above remain unchanged.
- **Compaction tool-cache prefix:** for a compaction without a provider summary block, the fork keeps the initial tool list plus the checkpoint's separate update (see [Compaction prompt and tool state](lifecycle-checklist.md#compaction-prompt-and-tool-state)). Anthropic uses that list unchanged only with both `supportsMidConvoSystemMessages` and `supportsMidConvoToolChanges` and at least one initial tool. It sends each block of immediately following system messages separately, with a cache breakpoint on the last leading tool change. Other routes use `resolveTranscript()` to fold leading tool changes into the first list; prompt text and section patches stay in place when the model supports them, otherwise all system messages collapse. Let the bundled factory own this choice: pre-folding the native Anthropic transcript loses its prefix benefit. Official Pi's native compaction checkpoint already holds the current tools; use its manager and bundled provider factory and accept that a changed list can invalidate the prefix, not a private checkpoint rewrite. The fork also exports `getNetToolChanges()`<!-- fork-only --> (replay gives the exact definitions and order, unlike the set comparison `getToolStateChanges()`) and `countLeadingSystemMessages()`<!-- fork-only --> (the consecutive system-message count before the first other role). Neither helper exists on official Pi: consume the intact transcript with shared `getCurrentTools()`/`getCurrentSystemPrompt()` and let `SessionManager` own compaction, without unconditional helper imports. Sources: `packages/ai/src/utils/transcript.ts` and `packages/ai/src/api/anthropic-messages.ts`. These source checks do not measure live cache hits.
- **Provider summary APIs:** the fork's pi-ai root exports `ProviderSummaryRequest`<!-- fork-only -->, `ProviderSummary`<!-- fork-only --> and `supportsProviderSummary`, plus `wroteProviderSummary()`<!-- fork-only --> (provider/API/model identity), `getProviderSummaryStandIn()`<!-- fork-only --> (the visible block summary as a user message, or an unavailable-summary notice), and `resolveProviderSummary()`<!-- fork-only --> (that stand-in before the kept messages for another model). `StreamOptions.providerSummary` requests a signed block instead of a normal reply; it arrives as `AssistantMessage.providerSummary`. Later input carries it on the leading `SystemMessage.providerSummary`. Anthropic normally adds the `compact-2026-09-04` beta and sends no message thread for requests asking for or carrying a block. Explicit `anthropic-beta` headers replace the generated beta list, and a null header disables it; preserve the required beta when overriding headers. Other APIs can ignore the request option and reply normally, so check the helper before dispatch. The coding-agent's `ModelRuntime` applies stand-in resolution before dispatch; a standalone provider owner must preserve equivalent model-switch handling. On official Pi, keep ordinary text summarization and shared transcript/model-runtime APIs, without imports or requests for these fork-only additions. Extension authors should use [Provider summary compactions](lifecycle-checklist.md#provider-summary-compactions), not hand-assemble or edit a signed block. Sources: `packages/ai/src/{provider-summary,types}.ts`, `packages/ai/src/api/anthropic-messages.ts` and `src/core/model-runtime.ts`.
- **Anthropic drop diagnostics:** preserve `anthropic_input_transformations`. On the fork, `anthropic_thinking_blocks`<!-- fork-only --> records `details.sent` and `details.dropped` when either count is above zero: the thinking blocks in the actual request body and those Anthropic dropped. A thread continuation can have neither, so absence is not proof of retained reasoning. A positive sent count and zero dropped on the first reply after a block compaction are the recorded evidence that kept reasoning survived. The fork announces drops beyond the highest earlier report since compaction, or beyond its retained thinking blocks before a report exists; a compaction with a provider summary block instead expects zero drops, so its first drop is announced. Expected ordinary-compaction drops and repeated thread reports are not re-announced. A cause appears only when all dropped blocks give the same recognized reason. Official Pi compares only the previous assistant response and has no count diagnostic; inspect its native transformations and request path. Do not rewrite history to silence a notice. Sources: `packages/ai/src/api/anthropic-messages.ts` and `src/modes/interactive/interactive-mode.ts` on each host.

## Validation and safety

- Validate registration with `--list-models`, auth configured/unconfigured states, thinking-level enumeration, and one real or stubbed stream for each custom request path.
- For dynamic catalogs, test cached/offline startup, successful refresh, fetch-failure retention, persistence-failure non-publication, abort, stale-generation suppression, forced refresh, and the actual mode that should trigger network work.
- For llama.cpp, validate unloaded, loaded, server-down, abort/timeout, and reload states without publishing images or copying credentials into artifacts. Treat download and load/unload as explicit local mutations; do not perform them during read-only inspection.
- For remote model smokes, inject only the needed credential into the model-only process, avoid package/lifecycle scripts, use `-p` with `--no-session`, set a verified thinking level, and save separate non-secret artifacts.
